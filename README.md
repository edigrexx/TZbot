# TZbot — время встреч во всех зонах команды

Отмечаете бота в сообщении со временем (или отвечаете на такое сообщение с отметкой) — он отвечает одним сообщением: исходное время и пересчёт во все зоны из `TIMEZONES`.

```
📅 Вторник, 15 сентября, 17:00 (MSK)

MSK      17:00  UTC+3
Almaty   19:00  UTC+5
Bishkek  20:00  UTC+6
Vietnam  21:00  UTC+7
```

LLM (через [OpenRouter](https://openrouter.ai)) **только** достаёт из текста дату, время и зону. Весь пересчёт делает Python через `zoneinfo`.

## Как пользоваться

| Сообщение в группе | Что разбирает бот |
|---|---|
| `Встреча в четверг в 17:00 по алматы @IQTimeDateSync_bot` | этот же текст (отметка может стоять где угодно) |
| реплай на «давайте в пол десятого» с текстом `@IQTimeDateSync_bot` | сообщение, на которое ответили |
| `Встреча в 12:00 завтра по бишкеку /time` | этот же текст: `/time` работает в любом месте вместо отметки |
| реплай с цитатой фрагмента + отметка | только процитированный фрагмент |
| `завтра после обеда @IQTimeDateSync_bot` | 14:00 с пометкой «приблизительно» |
| `через полтора часа @IQTimeDateSync_bot` | момент сообщения + 90 минут (считает Python) |
| `ок, договорились @IQTimeDateSync_bot` | «Не нашёл в сообщении времени встречи» |
| `@IQTimeDateSync_bot` без текста и не реплаем | подсказка по использованию |

В личке бот разбирает любое сообщение, отметка не нужна.

Если в реплае с отметкой есть и свой текст (`@IQTimeDateSync_bot а по Вьетнаму?`), бот сначала ищет время в этом тексте. Если там его нет, разбирает сообщение, на которое ответили.

«Сегодня», «завтра», «в понедельник» и «через час» отсчитываются от **момента написания исходного сообщения** в зоне его автора. Поэтому реплай на вчерашнее «завтра в 10» даст правильную дату.

## Настройка в BotFather

1. `/newbot`: получите `BOT_TOKEN`.
2. `/setprivacy` → выберите бота → **Disable**. Статус должен стать *Privacy mode is disabled*.
3. `/setjoingroups` → **Enable**, чтобы бота можно было добавить в группу.
4. Добавьте бота в группу **обычным участником**, админские права не нужны. Если бот уже был в группе, **удалите его и добавьте заново**: Telegram применяет смену privacy mode только при входе в группу.

Меню команд (`/time`, `/help`) бот регистрирует сам при старте.

### Почему privacy mode выключен

С включённым privacy mode Telegram доставляет боту в группе только четыре вида сообщений ([документация](https://core.telegram.org/bots/features#privacy-mode)):
- команды в начале сообщения (`/time@бот ...`);
- общие команды вроде `/start`, если последним в группе писал именно этот бот;
- сообщения, отправленные через его inline-режим;
- реплаи на сообщения самого бота.

Отметка `@бот`, `/time` в середине текста и реплай на чужое сообщение с отметкой до бота просто не доходят. Удобный сценарий «отметил — получил ответ» без выключения privacy mode невозможен.

Что это значит для приватности:
- Telegram присылает боту все сообщения группы, кроме сообщений других ботов.
- Сообщение без отметки или `/time` бот отбрасывает сразу, в первой проверке: оно не пишется в логи, не уходит в модель и нигде не хранится.
- В логах aiogram по каждому обновлению остаётся строка `Update id=… is handled` без текста.
- Если это недопустимо, включите privacy mode обратно (и перезайдите ботом в группу). Тогда будет работать только `/time …` в **начале** сообщения.

## Переменные окружения

| Переменная | Обязательна | По умолчанию / пример |
|---|---|---|
| `BOT_TOKEN` | да | `123456:AA...` |
| `OPENROUTER_API_KEY` | да | `sk-or-v1-...` ([ключи](https://openrouter.ai/settings/keys)) |
| `TIMEZONES` | да | `Almaty:Asia/Almaty,MSK:Europe/Moscow,Bishkek:Asia/Bishkek,Vietnam:Asia/Ho_Chi_Minh` |
| `DEFAULT_TZ` | да | `Asia/Almaty` |
| `USER_TIMEZONES` | нет | `@nguyen:Asia/Ho_Chi_Minh,123456789:Europe/Moscow` |
| `OPENROUTER_MODEL` | нет | `google/gemini-3.1-flash-lite` |
| `OPENROUTER_FALLBACK_MODELS` | нет | `google/gemini-2.5-flash-lite`; пустое значение отключает запасные |
| `OPENROUTER_REASONING_EFFORT` | нет | пусто (не передавать); `none`, `minimal`, `low`, `medium`, `high` |
| `LOG_LEVEL` | нет | `INFO` |

При старте проверяется формат `TIMEZONES` и существование каждой зоны. При ошибке процесс завершается с понятным сообщением, например `TIMEZONES: зона «Europe/Moskva» (MSK) не найдена в базе IANA`.

`USER_TIMEZONES` задаёт зону по умолчанию для конкретного автора. Если коллега из Вьетнама пишет «в 15:00» без зоны, время считается по Хошимину, а не по `DEFAULT_TZ`. Авторы не из списка получают `DEFAULT_TZ`.

## Выбор модели

Задача простая: короткий JSON из одной фразы. Один запрос — это примерно 1–1,5 тыс. входных токенов (в основном системный промпт) и около 50–100 выходных. Поэтому даже «дорогая» модель стоит доли цента за запрос. Выбирать стоит по качеству понимания русских разговорных форм и по скорости.

| Модель | Цена вход / выход, $ за 1 млн токенов | ≈ $ за 1000 запросов | Комментарий |
|---|---|---|---|
| `google/gemini-3.1-flash-lite` | 0.25 / 1.50 | 0.4 | **по умолчанию**: быстрая, хороший русский, strict JSON |
| `google/gemini-2.5-flash-lite` | 0.10 / 0.40 | 0.15 | **запасная**: самая дешёвая из надёжных, без рассуждений по умолчанию |
| `openai/gpt-5.4-nano` | 0.20 / 1.25 | 0.5 | думающая модель: медленнее; при задержках попробуйте `OPENROUTER_REASONING_EFFORT=minimal` |
| `anthropic/claude-haiku-4.5` | 1.00 / 5.00 | 1.6 | если бюджетные модели путаются во фразах |

Цены взяты из каталога OpenRouter на сентябрь 2026 и могут меняться. Модель вызывается только при обращении к боту, остальная переписка чата ничего не стоит.

Перед запуском прогоните кандидатов на наборе фраз вашим ключом, это стоит центы:

```bash
OPENROUTER_API_KEY=sk-or-... python scripts/try_models.py
```

```bash
OPENROUTER_API_KEY=sk-or-... python scripts/try_models.py google/gemini-3.1-flash-lite qwen/qwen3.8-flash
```

Скрипт для каждой модели выводит, какие фразы разобраны верно, задержку и фактическую стоимость. Выбранную модель укажите в `OPENROUTER_MODEL`.

## Деплой в Dokploy

1. **Create Service → Compose**, источник: этот репозиторий, путь `docker-compose.yml`.
2. На вкладке **Environment** задайте `BOT_TOKEN`, `OPENROUTER_API_KEY` и при необходимости остальные переменные. Dokploy кладёт их в `.env` рядом с compose-файлом, а compose подставляет их через `${...}`.
3. **Deploy**. Домен, порты и сеть не нужны: бот работает через long polling и делает только исходящие соединения. Если на токене остался webhook от прошлого деплоя, бот удалит его при старте и напишет об этом в лог.
4. Логи: вкладка **Logs** сервиса. Запускайте одну реплику: два процесса с одним токеном конфликтуют на `getUpdates`.

## Устройство

```
bot/
  __main__.py   запуск, long polling, меню команд, снятие webhook
  handlers.py   aiogram: отметка или /time в любом месте, реплай, цитата, личка
  mentions.py   поиск и вырезание обращений к боту (смещения в UTF-16)
  extractor.py  вызов OpenRouter: JSON-схема, запасные модели, таймаут 10 с, ошибки → текст для чата
  prompt.py     системный промпт: момент сообщения, календарь на 14 дней, зоны команды
  parsing.py    строгая валидация JSON модели
  convert.py    пересчёт через zoneinfo, сортировка по UTC-смещению, форматирование
  service.py    текст → модель → валидация → ответ; логирование каждого разбора
  config.py     разбор переменных окружения
scripts/
  try_models.py сравнение моделей на наборе фраз
```

Контракт ответа модели (неиспользуемые поля — `null`):

```json
{"found": true, "date": "2026-09-15", "time": "17:00", "tz": "Europe/Moscow", "tz_explicit": true, "approximate": false, "offset_minutes": null}
{"found": true, "offset_minutes": 90, "tz": "Asia/Almaty", "tz_explicit": false, "approximate": false, "date": null, "time": null}
{"found": false, "date": null, "time": null, "tz": null, "tz_explicit": null, "approximate": null, "offset_minutes": null}
```

- `approximate`: время истолковано приблизительно.
- `tz_explicit`: зона названа в тексте. Если нет, бот пишет, по какой зоне считал.
- `offset_minutes`: для «через N минут/часов». Модель не складывает время, это делает Python.

Формат задаётся через `response_format: json_schema` со `strict: true`. OpenRouter передаёт схему провайдеру, но насколько строго она соблюдается, зависит от провайдера. Поэтому ответ всегда проверяется в Python: `try/except json.JSONDecodeError`, `tz` должен быть в `zoneinfo.available_timezones()`, дата и время разбираются строго (`2026-02-30`, `24:00`, `9:30` отклоняются). Время, попавшее в «дыру» при переводе часов, тоже отклоняется.

Если основная модель недоступна, упёрлась в лимит или вернула ошибку, OpenRouter сам переключается на запасную (параметр `models`). В логах видно, какая модель ответила, сколько токенов ушло и сколько это стоило.

## Логи и приватность

Логируются только обращения к боту:
- строка `обращение …` со структурой сообщения: был ли реплай, есть ли текст, цитата; без самих текстов;
- разбор: исходный текст, момент написания, сырой ответ модели, результат или ошибка, модель, токены, стоимость.

Эти тексты уходят в логи Dokploy, в OpenRouter и провайдеру выбранной модели. Остальная переписка группы не логируется и никуда не отправляется.
