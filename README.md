# TZbot — время встреч во всех зонах команды

Упоминаете бота — он отвечает одним сообщением: исходное время и пересчёт во все зоны из `TIMEZONES`.

```
📅 Вторник, 15 сентября, 17:00 (MSK)

MSK      17:00  UTC+3
Almaty   19:00  UTC+5
Bishkek  20:00  UTC+6
Vietnam  21:00  UTC+7
```

Модель (Claude Haiku 4.5) **только** достаёт из текста дату, время и зону. Весь пересчёт делает Python через `zoneinfo`.

## Как пользоваться

| Сообщение в чате | Что разбирает бот |
|---|---|
| `@tzbot созвон завтра в 17:00 по мск` | текст этого же сообщения |
| реплай на «давайте в пол десятого» с текстом `@tzbot` | сообщение, на которое ответили |
| реплай с цитатой фрагмента + `@tzbot` | только процитированный фрагмент |
| `/time в пятницу в 9 утра по Бишкеку` | аргумент команды |
| `@tzbot завтра после обеда` | 14:00 с пометкой «приблизительно» |
| `@tzbot через полтора часа` | момент сообщения + 90 минут (считает Python) |
| `@tzbot ок, договорились` | «Не нашёл в сообщении времени встречи» |

В личке бот разбирает любое сообщение, упоминание не нужно.

Если в реплае есть и свой текст, и упоминание (`@tzbot а по Вьетнаму?`), бот сначала ищет время в этом тексте. Если там его нет, разбирает сообщение, на которое ответили.

«Сегодня», «завтра», «в понедельник» и «через час» отсчитываются от **момента написания исходного сообщения** в зоне его автора. Поэтому реплай на вчерашнее «завтра в 10» даст правильную дату.

## Настройка в BotFather

1. `/newbot`: получите `BOT_TOKEN`.
2. `/setprivacy` → выберите бота → **Enable**. Это значение по умолчанию; проверьте, что статус *Privacy mode is enabled*.
3. `/setjoingroups` → **Enable**, чтобы бота можно было добавить в группу.
4. Необязательно: `/setcommands` → `time - Пересчитать время в зоны команды`.
5. Добавьте бота в группу **обычным участником**.

Что важно про privacy mode:
- С включённым режимом Telegram присылает боту только сообщения с `@упоминанием`, команды и реплаи на его собственные сообщения. В сообщение с упоминанием Telegram вкладывает `reply_to_message`, поэтому сценарий «реплай + упоминание» работает без чтения чата.
- **Не делайте бота администратором группы.** На админов privacy mode не действует: Telegram начнёт присылать все сообщения. Код всё равно проигнорирует сообщения без упоминания, но они будут уходить на сервер.
- Если режим меняли, когда бот уже был в группе, удалите его из группы и добавьте снова: настройка применяется при входе.
- Реплаи на сообщения бота без упоминания бот получает, но молча отбрасывает и не логирует.

## Переменные окружения

| Переменная | Обязательна | Пример |
|---|---|---|
| `BOT_TOKEN` | да | `123456:AA...` |
| `ANTHROPIC_API_KEY` | да | `sk-ant-...` |
| `TIMEZONES` | да | `Almaty:Asia/Almaty,MSK:Europe/Moscow,Bishkek:Asia/Bishkek,Vietnam:Asia/Ho_Chi_Minh` |
| `DEFAULT_TZ` | да | `Asia/Almaty` |
| `USER_TIMEZONES` | нет | `@nguyen:Asia/Ho_Chi_Minh,123456789:Europe/Moscow` |
| `ANTHROPIC_MODEL` | нет | `claude-haiku-4-5-20251001` |
| `LOG_LEVEL` | нет | `INFO` |

При старте проверяется формат `TIMEZONES` и существование каждой зоны. При ошибке процесс завершается с понятным сообщением, например `TIMEZONES: зона «Europe/Moskva» (MSK) не найдена в базе IANA`.

`USER_TIMEZONES` задаёт зону по умолчанию для конкретного автора. Если коллега из Вьетнама пишет «в 15:00» без зоны, время считается по Хошимину, а не по `DEFAULT_TZ`. Авторы не из списка получают `DEFAULT_TZ`, как в ТЗ.

## Запуск

Локально (Python 3.12):

```bash
python3.12 -m venv .venv && . .venv/bin/activate && pip install -r requirements-dev.txt
```

```bash
cp .env.example .env
```

```bash
set -a && . ./.env && set +a && python -m bot
```

Тесты (без сети и без ключей, ответ модели подменяется):

```bash
python -m pytest
```

Docker:

```bash
docker compose up -d --build
```

## Деплой в Dokploy

1. **Create Service → Compose**, источник: этот репозиторий, путь `docker-compose.yml`.
2. На вкладке **Environment** задайте `BOT_TOKEN`, `ANTHROPIC_API_KEY` и при необходимости остальные переменные. Dokploy кладёт их в `.env` рядом с compose-файлом, а compose подставляет их через `${...}`.
3. **Deploy**. Домен, порты и сеть не нужны: бот работает через long polling и делает только исходящие соединения.
4. Логи: вкладка **Logs** сервиса. Запускайте одну реплику: два процесса с одним токеном конфликтуют на `getUpdates`.

## Устройство

```
bot/
  __main__.py   запуск, long polling
  handlers.py   aiogram: упоминание / реплай / цитата / команда / личка
  mentions.py   поиск и вырезание упоминания (смещения в UTF-16)
  extractor.py  вызов Claude: structured outputs, таймаут 10 с, ошибки → текст для чата
  prompt.py     системный промпт: момент сообщения, календарь на 14 дней, зоны команды
  parsing.py    строгая валидация JSON модели
  convert.py    пересчёт через zoneinfo, сортировка по UTC-смещению, форматирование
  service.py    текст → модель → валидация → ответ; логирование каждого разбора
  config.py     разбор переменных окружения
```

Контракт ответа модели:

```json
{"found": true, "date": "2026-09-15", "time": "17:00", "tz": "Europe/Moscow", "tz_explicit": true, "approximate": false}
{"found": true, "offset_minutes": 90, "tz": "Asia/Almaty", "tz_explicit": false, "approximate": false}
{"found": false}
```

К базовому контракту ТЗ добавлены три необязательных поля:
- `approximate`: время истолковано приблизительно;
- `tz_explicit`: зона названа в тексте. Если нет, бот пишет, по какой зоне считал;
- `offset_minutes`: для «через N минут/часов». Модель не складывает время, это делает Python.

JSON-формат задаётся через structured outputs (`output_config.format`), поэтому API не вернёт невалидный JSON или markdown-обёртку. Разбор с `try/except json.JSONDecodeError` и строгой проверкой полей всё равно остаётся.

Валидация: `tz` должен быть в `zoneinfo.available_timezones()`, дата и время разбираются строго (`2026-02-30`, `24:00`, `9:30` отклоняются). Время, попавшее в «дыру» при переводе часов, тоже отклоняется.

## Логи и приватность

Каждый разбор пишется в stdout: исходный текст, момент написания, сырой ответ модели, результат или ошибка. Логируются только сообщения, адресованные боту. Учтите, что эти тексты уходят в логи Dokploy и в Anthropic API.
